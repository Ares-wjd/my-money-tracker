# 기능 명세서 (v2.7)

> 2단계 "세부 기능 정하기"의 결과물. 3단계 기능 구현은 이 문서를 기준으로 한다.
> 이후 기능 추가·변경은 이 문서를 먼저 고친 뒤 구현한다.

## 0. 전체 구성

| 탭 | 내용 |
| --- | --- |
| 홈 | 투자 자산 요약 + 자산 추이 그래프 (보기 단위 선택) |
| 계좌 | 투자 계좌 → 보유 종목 관리 |
| 목표 | 목적통장 (투자 자산과 완전히 분리) |
| 설정 | 계정, 로그아웃, 계정·데이터 삭제, API 키(한국투자증권 / 수출입은행), 앱 버전·업데이트 확인 |

- 데이터는 Google 계정별로 Firebase Firestore 에 저장한다.
- **투자 자산**과 **목적통장**은 데이터·화면·통계 모두 분리한다. 목적통장은 홈 화면의 합계나 그래프에 들어가지 않는다.
- 통화: 원화(KRW)와 달러(USD)를 지원한다. 합계는 원화로 환산해 표시한다.
- 누구나 설치해 자기 Google 계정으로 쓸 수 있는 공개 앱이다. 보안 원칙은 5장 참고.

## 1. 투자 자산 (홈 / 계좌 탭)

### 1-1. 구조
```
투자 계좌 (예: 한투 국내, 한투 해외, 연금저축)
 ├─ 입출금 · 계좌 간 이체 기록   → 투자금 계산
 ├─ 보유 종목 (주식 / ETF / 펀드 / 채권 / 금현물, KRW 또는 USD)
 │   ├─ 매수·매도 기록 (날짜, 수량, 단가, 수수료, 세금)
 │   └─ 배당 기록 (날짜, 세후 금액)
 └─ 예수금 (원화 / 달러 각각)  → 한투 연결 계좌는 불러온 값, 그 외는 입력값 + 기록으로 계산 (혼합 방식)
```

- 계좌 정보: 이름, **종류**(일반(위탁) / ISA / 연금저축 / IRP / 퇴직연금(DC) / 금현물 / 기타), **계좌번호**, 메모

### 1-1-1. 금현물 (v2.7)
- 자산 유형 **금현물**: KRX 금시장 금 99.99 1kg (종목코드 **M04020000**, 1g 단위 매매, 가격은 1g당 원).
  - 금현물을 고르면 시장은 국내(원)로 고정되고, 종목코드가 비어 있으면 M04020000 을 넣는다 (미니금 100g 은 M04020100 으로 고쳐 쓴다).
  - 수량은 **g** 으로 표시한다 (예: "120g", 평균단가·현재가는 "1g당"). 기록 문구, 비중 탭 계산기("12g 매수")·매수 단위("1g 단위")도 같다.
  - 티커 자리에는 코드 대신 **"금현물"** 배지 (금색). 범례에 "금현물".
- 계좌 종류 **금현물** (금현물 통장): 금과 예수금(원화)만 있다. 이 계좌에서 종목을 추가하면 자산 유형이 금현물로 고정된다.
- 시세: 국내 현재가 조회에 금 종목코드를 넣어 받는다. 실패하면 국내 일별 시세의 가장 최근 종가를 쓴다.
  과거 시세(그래프)도 기간별 일봉 조회가 안 되면 일별 시세(최근 30 영업일)만 쓴다. 받지 못하면 현재가 직접 입력.

### 1-2. 입력하는 것
| 기록 | 항목 |
| --- | --- |
| 입금 / 출금 | 날짜, 금액, 통화. 투자금은 원화 기준이며, 달러 입출금은 그날 환율로 원화 환산 |
| 계좌 간 이체 | 날짜, 보내는 계좌, 받는 계좌, 금액, 통화(원화/달러). 보내는 계좌는 출금, 받는 계좌는 입금으로 처리되어 전체 투자금은 변하지 않음 |
| 매수 / 매도 | 날짜, 종목, 수량, 단가(종목 통화), **제비용**(제비용합 · 수수료 · 세금, 아래 참고) |
| 배당 | 날짜, 종목, **세후 실수령액**(종목 통화) |
| 환전 | 날짜, 방향(원화 → 달러 / 달러 → 원화), 원화 금액, 달러 금액, **환율(1달러당 원, v2.7)**. 셋 중 마지막으로 입력한 두 칸으로 나머지 한 칸을 자동 계산 (원화 ÷ 달러 = 환율, 원화 ÷ 환율 = 달러(센트 반올림), 달러 × 환율 = 원화(원 반올림)). 자동 칸에는 "자동 계산" 표시, 자동 칸을 고치면 가장 오래전에 입력한 칸이 자동이 된다. 기존 기록은 환율이 자동 칸. 저장은 원화·달러 금액만 (환율은 둘로 계산). 직접 입력 계좌의 예수금 계산에만 쓴다 (투자금은 바뀌지 않음). **환전 환율은 수수료가 포함된 값이라 평가금·환차익 계산에는 절대 쓰지 않는다** (평가금은 수출입은행 매매기준율, 없으면 직접 입력 환율) |
| 초기 보유분 | 앱을 처음 쓸 때 이미 가진 종목은 "현재 수량 + 평균단가 + 기준일"로 한 번에 등록. 기존 투자금·예수금도 기준일 값으로 한 번에 등록 |
| 예수금 | 증권사 앱에 보이는 예수금(원화·달러)과 기준일. 바뀌었을 때마다 다시 입력하며, 같은 날 다시 입력하면 덮어씀 |

- **제비용 입력 (v2.7)**: 매수·매도의 제비용합·수수료·세금을 한 묶음으로 입력하고 셋 다 저장한다.
  - 수수료·세금을 쓰면 제비용합은 그 합으로 자동 계산되고, 제비용합 칸은 회색(잠김)으로 표시만 한다.
  - 제비용합만 쓰면 수수료·세금 칸은 회색(잠김)이고 수수료 0, 세금 0, 제비용합 X 로 저장한다. 쓰던 칸을 비우면 다시 모두 쓸 수 있다.
  - 모든 계산(매수 비용, 실현손익, 원화 보기)은 **제비용합**으로 한다. 제비용합이 없는 예전 기록·한투에서 불러온 기록은 수수료 + 세금.
  - 다시 열면 수수료·세금이 있으면 나눠서, 없으면 제비용합으로 보여준다. 기록 목록에는 "수수료 1,200 · 세금 300" 또는 "제비용 1,500".

### 1-2-1. 표로 일괄 입력 (매수·매도, v2.7)
- 계좌 화면의 기록 추가 메뉴 → **[표로 일괄 입력]** (폰·웹). 한투 연결 계좌는 매수·매도를 불러오므로 메뉴가 없다.
- 제목 칸이 있는 **빈 표**: 날짜 / 매매구분 / 종목명 / 종목코드 / 평단가 / 수량 / 제비용합 + 인식 결과.
  - 엑셀·구글시트에서 복사한 칸(탭·줄바꿈으로 구분)을 **고른 칸부터 오른쪽·아래로** 채운다.
    열을 나눠서(예: 1~2열, 3~6열), 행을 나눠서(1~10줄, 11~20줄) 여러 번 붙여 넣을 수 있다. 줄이 모자라면 늘어난다.
  - 붙여 넣은 줄이 제목 줄(날짜·매매구분… 글자만 있음)이면 건너뛴다. 칸마다 직접 입력·수정, 줄 빼기, 표 비우기.
  - 줄 추가: [+ 5줄 추가] 또는 줄 수를 직접 넣고 [줄 추가].
  - 최대 300줄. 저장 전에 화면을 나가면 버릴지 묻는다.
- 읽는 규칙
  - 날짜: 2026-10-12, 2026.10.12, 2026. 10. 12, 2026/10/12, 20261012
  - **수량 부호 = 매수·매도** (표 일괄 입력에서만): 양수 = 매수, 음수 = 매도 (-3, −3, (3) 인식). 저장은 지금처럼 양수 수량 + 매수/매도.
    매매구분은 비워도 된다. 적었으면 부호와 맞아야 한다 ("매수"인데 음수, "매도"인데 양수는 오류 — 실수 확인용).
    매매구분: "매수"가 들어 있으면 매수, "매도"가 들어 있으면 매도 (buy/sell 도 인식). 매매 기록 입력 화면 등 다른 곳은 바뀌지 않는다.
  - 숫자: 쉼표·공백·"원"·"$" 무시. 제비용합이 비어 있으면 0 (제비용합으로 저장, 수수료·세금 0). 평단가는 그 거래의 단가(종목 통화, 금현물은 1g당).
  - 종목: 이 계좌에서 **종목코드**가 같은 종목 → (코드가 없으면) **이름**이 같은 종목. 없으면 **새 종목**으로 저장 때 함께 만든다.
    새 종목은 같은 코드끼리 하나로 묶고, 표 아래에서 시장·자산 유형을 고친다. 자동 추정: 다른 계좌에 같은 코드가 있으면 그 시장·유형,
    아니면 숫자로 시작하는 6자리 코드·코드 없음 = 국내, 그 외 영문 티커 = 해외(나스닥), M04020000 = 금현물, KODEX·TIGER 등 이름 = ETF, 나머지 주식.
- 인식 결과 (줄마다): "기존 종목 · 매수 10주", "새 종목 · 매도 3주" (금현물은 g), 오류(빨강: 날짜·매매구분·종목·평단가·수량·제비용합·매도 수량 초과),
  "중복 의심(저장 안 함)" — 날짜·종목·구분·수량·단가가 같은 기록이 이미 있으면 저장하지 않는다 (같은 표를 두 번 붙여 넣는 실수 방지).
  매도는 그날 보유 수량(이미 있는 기록 + 표의 다른 줄)보다 많으면 오류.
- [저장]: 오류 줄이 있으면 무엇을 고칠지 알려주고 저장하지 않는다. 새 종목 → 매매 기록 순으로 한꺼번에 저장.

### 1-2-2. 표로 일괄 입력 — 입출금·배당·환전 (v2.7)
- [표로 일괄 입력]을 누르면 **입출금 | 매매 | 배당 | 환전** 을 고른다 (폰·웹). 한투 연결 계좌는 매매를 불러오고 환전 기록을 쓰지 않으므로 입출금·배당만.
  이체는 표로 넣지 않고 직접 입력한다. 붙여넣기·줄 추가·인식 결과·중복 의심·저장 방식은 매매 표와 같다.
- **입출금 표**: 날짜 / 입출금 / 금액 (원화)
  - 금액 부호로 구분: 양수 = 입금, 음수 = 출금 (-3·−3·(3) 인식). 입출금 칸은 비워도 되고, 적었으면 부호와 맞아야 한다
    ("입금"인데 음수, "출금"인데 양수는 오류). 원화로 저장 (투자금 = 금액).
  - 같은 날·같은 구분·같은 금액의 입출금이 이미 있으면 중복 의심.
- **배당 표**: 날짜 / 종목코드 / 종목명 / 원화배당금 / 외화배당금 (세후 실수령액)
  - 이 계좌의 **종목코드**로 종목을 찾는다. 코드가 없거나 계좌에 없는 코드면 오류 (배당으로 새 종목을 만들지 않음).
  - 종목명은 확인용: 앱의 종목명과 다르면 저장하고 경고만 ("확인: 앱 종목명은 …", 띄어쓰기·대소문자 차이는 같은 이름).
  - 배당은 종목 통화로 저장: 국내 종목은 원화배당금, 해외 종목은 외화배당금 칸. 맞는 칸이 비면 오류, 반대 칸에 값이 있으면 쓰지 않는다고 알림.
  - 같은 날·같은 종목·같은 금액의 배당이 이미 있으면 중복 의심.
- **환전 표**: 날짜 / 달러→원화(체크박스) / 외화 / 환율 / 원화
  - 체크하지 않으면 원화 → 달러(달러 매수), 체크하면 달러 → 원화(달러 매도). 붙여 넣은 글은 TRUE·1·Y·O·V·✓·달러→원화·매도 = 체크,
    빈칸·FALSE·0·N·X·원화→달러·매수 = 해제, 그 밖의 글은 오류. 체크박스만 켜고 나머지가 빈 줄은 빈 줄.
  - 외화·환율·원화는 양수. 세 칸 중 두 칸만 있어도 나머지를 환전 입력과 같은 규칙으로 계산 (달러 센트·원화 원 단위 반올림).
    세 칸 모두 있으면 원화·외화를 저장하고, 환율이 원화 ÷ 외화와 0.5% 넘게 다르면 경고만 ("확인: 원화÷외화 = …").
  - 오류: 날짜, 방향 칸, 숫자 아님, 0 이하, 두 칸 미만. 같은 날·같은 방향·같은 원화·외화 금액의 환전이 이미 있으면 중복 의심.

### 1-3. 계산하는 것
- **투자금** = 입금 합계 − 출금 합계 (원화)
  - 계좌 상세 기록 목록에서 입금·출금·이체 기록의 금액 아래에 **누적 투자금**(그 계좌 기록을 날짜순·입력순으로 쌓아 그 기록까지 반영한 투자금,
    이체는 보낸 계좌 −·받은 계좌 +)을 작게 보여준다 (v2.7). 가장 최근 입출금 기록의 누적값 = 지금 투자금.
- **기록 유형 필터 (v2.7, 폰·PC)**: 계좌 상세 기록 목록 위에 유형 칩 (입금 · 출금 · 이체 · 매수 · 매도 · 배당 · 예수금 · 환전, 예전 "예수금 조정"이
  있으면 그것도 — 그 계좌에 있는 유형만). 여러 개 고를 수 있고 **기본은 전부 선택(= 전체)**. [전체] 칩은 모두 선택돼 있으면 전체 해제, 아니면 전체 선택.
  제목은 걸렀으면 "기록 12건 / 전체 40건", 하나도 고르지 않으면 "보여줄 유형을 고르세요". "기록 더 보기"는 걸러진 목록 기준.
  누적 투자금은 걸러 봐도 전체 기록 기준. 고른 필터는 이 기기·이 브라우저에 계좌마다 기억한다 (뺀 유형을 저장 → 새로 생긴 유형은 보임).
- **예수금**(통화별) — **혼합 방식 (v2.7)**
  - **증권사에서 불러오는 계좌**(한투에서 불러온 기록이 있는 계좌, 폰·웹 같은 규칙): 불러온 값만 쓴다. 날짜마다 그날 또는 이전에
    마지막으로 불러온 값, 첫 기록 이전은 0. 폰은 **하루에 한 번은 꼭** 그날 예수금을 기록한다 (그날 첫 새로고침, 바뀌면 그날 값을 덮어씀).
  - **직접 입력 계좌**: 입력한 예수금 = **기준점** (그날 기록이 모두 반영된 잔액). 그 사이는 기록으로 계산한다.
    - 기준점 이후 날짜 = 기준점 + 다음 날부터 그 날짜까지의 기록. 첫 기준점 이전 = 첫 기준점 − 그 사이 기록 (거꾸로 추정).
      입력한 적이 없으면 0원에서 시작해 기록만으로.
    - 기록별 변화: 입금 +, 출금 −, 이체 (보내는 계좌 −, 받는 계좌 +), 매수 −(수량 × 단가 + 제비용합), 매도 +(수량 × 단가 − 제비용합),
      배당 + (모두 그 통화, 종목은 종목 통화), 환전 (원화 → 달러면 원화 −원화 금액·달러 +달러 금액, 반대도 같음).
      초기 보유분 매수는 예수금에서 나간 돈이 아니므로 빼지 않는다. 예전 "예수금 조정" 기록은 쓰지 않는다.
    - 기록 추가 메뉴에 **[환전]** 을 다시 둔다 (직접 입력 계좌만, 원화 금액 + 달러 금액).
    - 계산값이 음수면 "기록을 확인하세요" 경고 (입금 기록 누락 등).
  - 계좌 상세 예수금 카드: 계산값이면 "10/1 입력 1,000,000원 + 이후 기록 −687,600원"처럼 근거를 보여준다.
    예수금 입력 창: 그날의 "계산값"과 입력값의 차이 ("차이 +2,600원 — 이자·수수료 등 기록되지 않은 금액").
  - 예탁금 이용료·이자 등은 **투자금이 아니다.** 예수금(다음 입력)을 통해 계좌 평가금에 포함되어 계좌 전체 수익(평가금 − 투자금)에 반영된다.
  - 그래프·홈·비중 탭은 모두 같은 예수금을 쓴다.
- **평균단가**: 이동평균법 (국내 증권사 기본 방식)
- **종목 평가금** = 보유 수량 × 현재가 (달러 종목은 × 환율)
- **계좌 평가금** = 종목 평가금 합계 + 예수금
- **수익금(배당 포함)** = 계좌 평가금 − 투자금
- **수익금(배당 미포함)** = 수익금(배당 포함) − 누적 배당
- **수익률** = 수익금 ÷ 투자금 (배당 포함 / 미포함 두 가지 모두 표시)
- 종목별로도 매수원금, 평가손익, 수익률(배당 포함/미포함)을 표시
- **보유 종목 정렬**: 계좌 상세의 보유 종목을 **평가금(기본) / 총 수익률 / 오늘 수익률** 순(높은 순)으로 바꿔 볼 수 있다.
  고른 기준은 기기마다 기억한다. 가격·수익률이 없는 종목은 맨 뒤. 총 수익률은 보기(원화/외화)를 따른다.
  - **오늘 수익률** = 현재가 ÷ 전일 종가 − 1. 폰이 시세 조회(한투) 때 전일 종가를 함께 받아 저장하고(한투 연결 계좌 종목도 시세 조회),
    웹은 저장된 값을 쓴다. 직접 입력한 가격을 쓰는 종목은 표시하지 않는다. 휴장일에는 마지막 거래일 등락률.
  - 각 종목 줄에 총 수익률과 오늘 수익률을 함께 보여준다.
- **티커 색 구분**: 국내 주식 초록, 해외 주식 남보라, ETF(국내·해외) 호박색, 금현물 금색, 펀드·채권 회색. 보유 종목 목록 위에 범례.
- **해외 종목 금액 보기 전환 (원화 / 외화)**: 계좌 상세의 보유 종목과 종목 상세에서 바로 바꿔 볼 수 있다.
  - 외화: 해외 종목은 달러, 국내 종목은 원화 (기본값). 원화: 해외 종목도 모두 원화로 표시.
  - 원화 보기는 **환차익을 반영**한다: 매입금액·평균단가는 **매수한 날의 환율**로 쌓고(이동평균), 평가금·현재가는 오늘 환율로 환산한다.
    실현손익은 매도한 날, 배당은 받은 날의 환율로 환산한다. 평가손익은 주가 손익(달러 손익 × 오늘 환율)과 환차익으로 나눠 보여준다.
  - 수익률은 보기를 따른다: 원화 보기는 원화 수익률(환차익 포함), 외화 보기는 달러 수익률.
  - 환율은 수출입은행 **매매기준율**(휴일이면 직전 영업일). 폰 앱이 해외 종목의 매매·배당 날짜 환율을 받아 저장하고(없는 날만), 웹은 저장된 값을 쓴다.
    아직 없는 날이 있으면 그 종목은 오늘 환율로 단순 환산하고 "매매일 환율 없음"을 표시한다.
  - 실제 증권사 환전 환율과는 차이가 날 수 있고, 한투 초기 보유분은 연결 시작일 환율로 계산된다.
  - 홈·계좌 전체 평가금·수익률은 원화 기준 하나만 보여준다 (투자금이 입금한 원화라 이미 환차익 포함).
  - 환율이 없으면 "환율 필요"로 표시. 해외 종목이 없는 계좌에서는 전환 버튼을 숨긴다.
  - 마지막 선택은 기기마다 기억한다 (폰·PC 웹 각각). 폰과 웹 모두 같은 방식.

### 1-4. 시세 자동 반영
| 자산 | 출처 | 비고 |
| --- | --- | --- |
| 국내 주식 · ETF | **한국투자증권 Open API** (현재가, 기간별 일봉) | 공식 API. 날짜별 종가로 과거 어느 날짜든 잔고 계산 가능 |
| 해외 주식 · ETF | **한국투자증권 Open API** (해외 현재가, 기간별 시세) | 미국 등 해외 거래소 |
| 환율 (USD/KRW) | 한국수출입은행 현재환율 API (무료 공식, 날짜별 조회, 매매기준율 사용) | 평가금 환산용. 명세는 `docs/API_NOTES.md` |
| 금현물 (KRX 금시장) | **한국투자증권 Open API** (국내 현재가, 안 되면 일별 시세) | 종목코드 M04020000, 1g당 가격 |
| 펀드 | 기준가 직접 입력 | 무료 공식 API 없음 |
| 채권 | 직접 입력 (현재 버전) | 장외채권은 시세 출처 없음. 경과이자 자동 추정은 추후 검토 |

- 한국투자증권 API 키(App Key / App Secret)와 수출입은행 환율 API 키는 **사용자가 각자 설정 화면에서 입력**하고,
  **클라우드에 올리지 않고 이 기기에만 암호화해 저장**한다. (다른 기기에서는 다시 입력)
  - 앱 안에 개발자의 키를 넣지 않는다 (APK 에서 키를 꺼낼 수 있고, 호출 한도를 모든 사용자가 나눠 쓰게 되므로).
  - 키가 없으면 시세·환율 자동 반영 대신 직접 입력만 가능하다고 안내한다.
- 접근 토큰은 하루 단위로 발급받아 기기에 보관하고 재사용한다 (토큰 발급 횟수 제한 대응).
- 한투 호출은 한 줄로 세워 간격을 둔다 (기본 0.25초). 초당 호출 한도에 걸리면 모든 호출을 1초 멈추고 간격을 늘리며(최대 1초),
  성공이 이어지면 다시 줄인다. 과거 시세 받기는 종목 사이마다 쉬어 잔고·현재가 새로고침이 먼저 나가게 한다.
  한도 오류는 "잠시 후 다시 받습니다"로 알리고 설정 열기 버튼은 띄우지 않는다.
- 시세 조회에 실패하면 마지막으로 받은 가격을 쓰고, 가격 옆에 기준일을 표시한다.
- 어떤 종목이든 가격을 직접 입력해 덮어쓸 수 있다.
- 시세는 다른 증권사 계좌의 종목에도 똑같이 적용된다 (종목 코드 기준).
- **홈·계좌 화면을 보는 동안 1분마다 현재가를 자동으로 새로 받는다** (앱이 화면에 있을 때만). 계좌 화면에도 새로고침 버튼을 둔다.
  - 한투 연결 계좌는 잔고 조회로 실제 예수금과 현재가를 함께 받는다 (호출 수 절약).
  - 현재가는 메모리에 두고 Firestore 에는 15분에 한 번만 저장한다. 환율은 30분에 한 번만 조회한다.

### 1-4-1. 한국투자증권 연결 계좌 자동 불러오기
KIS Developers 에 연결한 계좌(실전투자계좌, 종합계좌번호 8자리 + 상품코드)는 기록을 직접 입력하지 않고 API 로 불러온다.

| 불러오는 것 | 방식 |
| --- | --- |
| 잔고 (보유 종목, 수량, 평균단가, 예수금) | 국내·해외 잔고 조회 API |
| 매수·매도 체결 내역 | 국내 일별주문체결조회(3개월 이내/이전), 해외 체결내역 조회 API |
| 입출금(투자금), 배당 | 제공 API 가 확인되면 자동, 없으면 **직접 입력** |

- 대상은 연결된 종합계좌의 **주식(국내·해외) 상품**이다. 같은 종합계좌번호 아래의 CMA 는 KIS 안내상 API 대상이 아니므로 직접 입력한다.
- 계좌는 앱 안에서 "한투 연결 계좌"로 표시하고, 연결 정보(계좌번호·상품코드)는 API 키와 함께 기기에만 저장한다.
- 앱을 열 때(또는 새로고침할 때) 마지막으로 불러온 날 이후의 체결 내역만 새로 받아온다. 처음 연결할 때는 시작일을 정해 과거 내역을 한 번에 받는다.
- 불러온 체결은 주문번호로 중복을 걸러 매매 기록으로 저장한다. 직접 수정·삭제는 막고, 메모만 달 수 있다.
- **입금·출금(투자금)은 사용자가 직접 기록한다.** 연결 계좌에서는 매수·매도를 직접 추가하는 메뉴를 숨긴다 (불러온 기록과 중복 방지).
- **연결 계좌의 예수금은 한투 값(원화 D+2, 달러)을 불러온다.** 불러오기·새로고침 때 값이 바뀌었으면 그날의 예수금 기록으로 저장한다
  (바뀌지 않으면 저장하지 않음). 연결 계좌는 예수금 입력 버튼을 숨긴다.
- 미니스탁(소수점) 매매는 체결 내역에 나오지 않아, 잔고 수량과 비교해 "수량 맞춤" 기록으로 채운다.
- KIS 서비스는 **1년마다 갱신**이 필요하다 (만료 30일 전부터 포털에서 갱신 가능). 설정에 만료일을 입력받아 만료 30일 전부터 앱에서 안내하고,
  만료로 토큰 발급이 실패하면 "KIS 포털에서 서비스를 갱신하세요" 라고 알려준다.

### 1-5. 자산 추이 (보기 단위 선택)
- 그래프의 보기 단위를 **1일 / 5일 / 10일 / 1달 / 1년** 중에서 고를 수 있다.
  - 각 점은 그 날짜 기준의 **평가금 · 투자금 · 누적 배당**이다.
  - 1일·5일·10일은 가장 최근 날짜부터 거꾸로 그 간격마다 점을 찍는다. 1달은 매월 말, 1년은 매년 말 기준이며, 마지막 점은 항상 오늘이다.
  - 휴장일(주말·공휴일)은 직전 거래일 종가를 쓴다.
  - **시세가 없는 날의 가격 추정 (v2.7)**: 알고 있는 가격 = 저장된 종가 + 매수·매도 기록의 단가 (같은 날이면 종가, 같은 날 매매가 여러 번이면
    수량 가중평균, 같은 종목이면 다른 계좌의 기록도) + 직접 입력한 가격(날짜가 있으면). 어떤 날의 가격은
    ① 그날 알고 있는 가격 ② 앞뒤가 모두 종가이고 간격이 14일 이하면(휴일) 전 거래일 종가 ③ 그 밖(시세를 알 수 없는 기간)은 앞뒤로 알고 있는
    가격을 날짜 비율로 잇는다 (예: 1/1 매수 20만원, 1/3 종가 18만원 → 1/2 는 19만원) ④ 첫 가격 앞은 첫 가격, 마지막 가격 뒤는 마지막 가격.
    직접 입력한 가격이 그날 이전에 있고 더 최근이면 그 가격이 우선한다. "과거 종가가 없어 평가금이 낮게 나옴" 경고는 알고 있는 가격이 하나도 없는 종목만.
  - 금현물처럼 한투가 최근 기간만 주는 종목도 받은 종가는 지우지 않고 쌓으며, 폰을 열 때마다 마지막으로 받은 날 이후의 빈 날을 채운다.
  - 모든 보기 단위가 **첫 기록일부터 전체 기간**을 보여준다 (v2.7, "이전 기간 더 보기" 없음).
- 특정 날짜의 값 계산
  - 평가금 = 그날 보유 수량(매매 기록으로 계산) × 그날 종가 × 그날 환율 + 그날 예수금
  - 펀드처럼 직접 입력한 가격은 그날 이전에 마지막으로 입력한 가격을 쓰고, 채권은 그날까지의 경과이자로 계산한다.
- **일별 값 미리 계산·저장 (v2.7)**: 기록 + 일별 종가로 계산한 날짜별 값을 계좌마다 Firestore 에 저장해 두고, 그래프는 저장된 값을
  불러와 보여주기만 한다 (1일 단위로 전체 기간을 봐도 빠름). **오늘** 값은 저장하지 않고 현재가로 바로 계산한다.
  - 저장: users/{uid}/chartDaily/{계좌id} = { v, from(첫 기록일), to(계산한 마지막 날 = 어제), days: { 날짜: [평가금, 투자금, 누적 배당, 시세 없음 0|1] },
    recSig: { 날짜: 그날 기록의 요약값 }, accSig(종목·연결 여부·직접 환율 요약값), priceSig: { "시세키|연-월", "fx|연-월", "trade:시세키|연-월": 그달 종가·환율·매매 단가 요약값 },
    anchor(계산할 때의 첫 예수금 입력일 중 가장 늦은 통화의 날짜) }. "전체" 그래프는 계좌별 값을 더한다.
  - **다시 계산할 범위**: 계산할 때마다 지금 기록·종목·시세로 요약값을 만들어 저장된 것과 비교한다. 폰·PC 어디서 무엇을 바꿨든
    (기록 추가·수정·삭제, 표로 입력, 한투에서 불러오기) 같은 방식으로 찾는다.
    - 기록이 달라진 가장 이른 날, 종가·환율·(같은 종목 다른 계좌 포함) 매매 단가가 달라진 가장 이른 달의 1일, 저장한 마지막 날 다음 날 중
      가장 이른 날을 찾고, 새 가격 하나가 그 앞의 알고 있는 가격까지 추정값을 바꾸므로 그 계좌 종목들의 **바로 앞 알고 있는 가격의 날**부터
      어제까지 다시 계산한다.
    - 직접 입력 계좌는 첫 예수금 입력일 이전 예수금을 거꾸로 추정하므로, 그날(지금 또는 저장할 때의 첫 입력일) 이전이 바뀌면 그 계좌를 처음부터 다시 계산한다.
    - 종목 정보(시장·코드·직접 입력 가격 등)·한투 연결 여부·직접 입력 환율이 바뀌었거나 첫 기록일이 바뀌었으면 그 계좌를 처음부터 다시 계산한다.
    - 계좌를 지우면 그 계좌의 저장값도 지운다.
  - 요약값은 폰·PC 가 똑같이 만든다: 칸을 정해진 순서로 이어 붙인 글(숫자는 64비트 실수 비트를 16진수로)의 FNV-1a 32비트 해시.
  - 폰·PC 모두 계산한다 (폰은 시세를 받은 뒤 뒤에서, PC 는 화면이 멈추지 않게 조금씩 나눠서). 과거 시세를 받는 중에는 끝난 뒤 계산한다.
    계산하는 동안 그래프에 "그래프 계산 중" 표시, 아직 계산하지 않은 날은 점을 빼고 보여준다.
  - 설정의 **[그래프 전체 다시 계산]**: 모든 계좌를 처음부터 다시 계산한다. 처음 업데이트하면 저장값이 없으므로 한 번 자동으로 전체 계산한다.
  - 일별 종가와 환율은 한 번 받으면 저장해 두고(캐시), 새로 필요한 날짜만 API 로 받아온다.
- **과거 시세 미리 저장 (v2.7)**: 그래프는 저장된 종가·환율만 쓴다 (보기 단위를 바꿔도 조회하지 않음 → 빠르고, PC 웹도 같은 값).
  - 종가: 종목(시세 키)마다 **첫 매수일 − 7일 ~ 다 판 날**(보유 중이면 어제까지, 오늘은 현재가). 같은 종목은 계좌가 달라도 합친다.
  - 환율: 해외 종목·달러 기록 중 가장 이른 날 − 7일 ~ 어제의 일별 매매기준율 (휴일은 "없음"으로 저장해 다시 묻지 않음).
    수출입은행 하루 호출 한도(1,000회) 때문에 하루 최대 600회까지, 최근 날짜부터 채운다 (길면 며칠에 걸쳐 채워짐).
  - **환율 확인 방식 (v2.7)**: 과거 환율은 바뀌지 않으므로 잘못 받은 값이 고정되지 않게 구간별로 다르게 받는다.
    - **오늘**: 30분마다 받아 오늘 평가금에만 쓴다 (marketData/fx_USD_checked 의 latest·latestDate, 과거 환율 목록에는 넣지 않음).
    - **최근 1주일**(어제 ~ 7일 전): 앱을 열 때와 그 뒤 3시간마다 날짜별로 다시 받아 저장된 값을 새 값으로 바꾼다 (fx_USD 의 rates, 고정하지 않음).
    - **1주일보다 오래된 과거**: 같은 날짜를 두 번 받아 같으면 고정 저장 (fx_USD_checked 의 rates), 다르면 한 번 더 받아 세 번 중 두 번 같은
      값을 저장, 셋 다 다르면 저장하지 않고 다음에 다시. "환율 없음"(휴일, -1)도 두 번 다 없어야 고정. fx_USD 에 이미 있는 값
      (최근 1주일에 받은 값·예전에 한 번만 받은 값)은 첫 번째로 보고 한 번만 더 받아 비교한다. 고정된 날짜는 다시 받지 않는다.
    - 매매일 환율(원화 보기)도 같은 규칙. 계산에 쓰는 환율 = fx_USD 의 값 위에 fx_USD_checked 의 고정 값을 덮은 것 (폰·PC 같음).
  - 폰이 앱을 열어 시세를 새로고침한 뒤 뒤에서 받는다 (30분에 한 번 확인, 기록을 저장하면 바로 확인). 처음 한 번은 전체 기간,
    그다음부터는 새로 생긴 날짜·새로 필요한 기간만. 저장된 범위를 먼저 읽은 뒤 판단해 이미 받은 기간은 다시 받지 않는다.
  - 받는 동안 그래프에 "과거 시세를 받는 중" 표시. PC 웹은 아직 없는 날이 있으면 "폰 앱에서 과거 시세를 받는 중" 안내.
- 홈 화면
  - 투자 자산 총 평가금, 투자금, 수익금·수익률(배당 포함/미포함)
  - **자산 추이 그래프**: 평가금 선과 투자금 선, 점을 누르면 그 날짜의 값 표시
    - **금액 보조선 (폰·PC 같음)**: 딱 떨어지는 금액(예: 1,000만 · 2,000만)에 가로 보조선 3~5개, 그래프 왼쪽에 금액("1,000만", "1.5억").
      간격은 (최대 − 최소) ÷ 4 이상인 1·2·2.5·5 × 10ⁿ 중 가장 작은 값, 그래프 위아래 끝은 첫·마지막 보조선.
  - 직전 점 대비 증감, 계좌별·자산 유형별 비중
  - 전체 계좌 합계뿐 아니라 계좌 하나만 골라서 볼 수도 있다.

### 1-6. 비중 (비중 탭, v2.6)
목표 비중과 실제 비중을 비교해, 비중에 맞춰 사는지 확인한다. 아래 탭: **홈 · 계좌 · 비중 · 목표 · 설정** (웹은 왼쪽 메뉴에 "비중").

- **비중 설정**을 이름을 붙여 여러 개 만든다 (예: "ISA 자산배분", "미국 개별주"). 설정마다:
  - 대상 계좌 (여러 개 가능 — 같은 종목은 합쳐서 계산), 종목별 목표 %, 예수금 포함 여부, **허용 범위**(기본 5/25 룰, 아래).
  - **제외할 종목**: 대상 계좌의 종목 중 [제외]를 고른 종목은 비중 계산(합계·실제 비중·도넛·표·계산기)에서 빠진다
    (예: 한투 계좌에서 삼성전자 제외). 같은 종목이 여러 대상 계좌에 있으면 모두 빠진다. 비중 화면에 "제외: …"로 표시.
  - 종목 목록은 대상 계좌의 종목 전체 (0주 종목 포함 — 아직 안 산 종목도 목표에 넣을 수 있다).
  - **계좌에 없는 종목 직접 추가**: 시장(국내/해외)·이름(필수)·종목코드(선택)를 넣어 목표에 넣는다
    (아직 사지 않은 종목, 상장 전 공모주, 장외 채권 등). 실제 0%로 보이고 매수 계산기 금액에도 들어간다.
    - 현재가를 불러오지 않으므로 **현재가를 직접 입력**할 수 있다 (국내 원, 해외 달러). 넣으면 주 수·1주 단위 계산이 된다.
    - 종목코드가 있으면 나중에 그 종목을 계좌에 추가·매수할 때 자동 연결된다 (평가금·현재가 반영).
    - 종목코드가 없으면 편집 화면의 [계좌 종목으로 바꾸기]로 실제 종목을 골라 목표 %·매수 단위를 옮긴다.
  - **지금 매수 안 함** (종목마다): 비중 표·도넛에는 그대로 보이지만 매수 계산기(사기만·사고팔기)에서 빠진다
    (예: 비상장이라 아직 살 수 없는 종목). 나머지 종목은 **원래 목표**까지 부족한 만큼 먼저 채우고, 남는 돈은 나머지 종목의
    목표 비율로 나눈다 (빠진 종목 몫을 현금으로 남기지 않는다). 계산기 아래에 "지금 매수 안 함: …"을 표시한다.
  - **매수 단위** (종목마다): 비워 두면 1주 단위, 금액(원)을 넣으면 그 금액 단위 (소수점 매수, 예: 1,000원).
    [일괄 적용]으로 모든 종목에 같은 단위를 넣고 종목별로 다시 고칠 수 있다. 새로 생긴 종목은 1주 단위.
  - 목표 합계가 100% 가 아니면 "합계 95% · 5% 남음"으로 알려주고 저장하지 않는다.
- 종목은 국내/해외 + 종목코드로 구분한다 (예: KR:005930, US:VOO — 해외는 거래소를 구분하지 않는다.
  코드가 없는 펀드·채권은 종목 하나로). 비중은 원화 평가금 기준.
- 실제 비중 = 종목 평가금 ÷ 합계 (예수금 포함이면 합계에 예수금도). 차이 = 실제 − 목표 (%p).
- **허용 범위 (5/25 룰, v2.7)**: 종목마다 목표 비중 W 에 따라 허용 편차를 정한다.
  - 허용 편차 ΔW = min(A, W × R). 절대 기준 A (기본 5%p), 상대 기준 R (기본 25%). 설정마다 고칠 수 있고 [5/25 기본값] 버튼.
    둘 중 하나를 비우면(0) 그 기준은 쓰지 않는다 (둘 다 비울 수는 없음). R 은 0~100%.
  - 상한 = W + ΔW, 하한 = max(0, W − ΔW). 예: 목표 40% → ±5%p (35~45%), 목표 10% → ±2.5%p (7.5~12.5%).
  - 실제 비중이 범위를 벗어나면(|차이| ≥ ΔW) 강조한다. **목표 0% 종목(예수금 포함)은 강조하지 않는다.**
  - 표의 목표 아래에 허용 범위(예: "7.5~12.5%"), 표 위에 사용 중인 기준과 "허용 범위 밖 n종목".
  - 예전 설정(차이 강조 기준 ±3%p 등)은 절대 기준 A 로 옮기고 상대 기준은 쓰지 않는다 (강조 결과가 바뀌지 않음). 새 설정은 5/25.
  - **상단·하단 따로 (v2.7)**: [☑ 상단·하단 같은 기준] (기본 켬). 끄면 상단(초과)·하단(부족) 기준을 따로 넣는다.
    상단 편차 = min(A상단, W × R상단), 하단 편차 = min(A하단, W × R하단). 상한 = W + 상단 편차, 하한 = max(0, W − 하단 편차).
    실제가 목표보다 높으면 상단 편차, 낮으면 하단 편차와 비교해 강조한다. 예: 상단 10%p·50%, 하단 5%p·25% →
    목표 40% → +10%p / −5%p (35~50%), 목표 10% → +5%p / −2.5%p (7.5~15%).
    끄면 상단 칸은 지금 값으로 시작, 다시 켜면 하단 값 하나로. [5/25 기본값]은 둘 다 5/25 로 되돌리고 체크를 켠다.
    줄마다 A·R 중 하나는 넣어야 한다. 기준 표시: "5/25 룰" 또는 "상단 10/50 · 하단 5/25".
- 허용 범위를 벗어나면 강조하고 "부족 / 초과" 태그로 표시한다. 방향마다 색을 달리한다:
  부족 = 파랑(줄 배경 옅은 파랑, 태그 진한 파랑), 초과 = 빨강(줄 배경 옅은 빨강, 태그 진한 빨강).
  태그 글자는 밝은 모드 흰색·다크 모드 검정 (대비 4.5:1 이상), 색만으로 구분하지 않도록 글자를 함께 쓴다.
- **도넛 그래프**: [실제 | 목표 | 비교] 선택. 비교는 바깥 고리 실제, 안쪽 고리 목표. 같은 종목은 같은 색,
  색은 색각 이상 구분 검사를 통과한 8색 팔레트 (도넛 처음·끝이 맞닿아도 구분됨). 9~16번째 종목은 같은 8색에 빗금 무늬를 넣어
  구분하고(범례 색 상자도 같은 빗금), 17개 이상일 때만 작은 것부터 "기타"로 묶는다 (표에는 모두).
- **매수 계산기**: 넣을 돈을 입력하면 **팔지 않고 사기만 해서** 목표에 가장 가깝게 되도록 종목별 금액·주 수
  (해외는 달러 금액도)를 보여준다. **상대 비중 기준 (v2.7)**: 금액 차이가 아니라 목표 대비 얼마나 채웠는지로 나눈다.
  - 채운 정도 = 지금 평가금 ÷ 목표 금액 (목표 금액 = 넣은 뒤 합계 × 목표 비중).
  - 채운 정도가 가장 낮은 종목부터 사서 다음으로 낮은 종목과 같아지면 함께 올린다 (모두 같은 채운 정도 L 까지:
    종목별 살 금액 = max(0, L × 목표 금액 − 지금 평가금), 그 합 = 넣을 돈). 목표가 큰 종목이 금액 차이가 크다는 이유만으로
    먼저 받지 않는다. 예: 목표 15% 를 78% 채운 종목보다 목표 5% 를 10% 채운 종목을 먼저 산다.
  - 모두 100% 를 채우고도 남으면 목표 비율대로 나뉘는 효과 (이미 초과인 종목은 나머지가 따라잡은 뒤에 산다).
  - 그다음 종목별 매수 단위(1주 가격 또는 금액 단위)로 내림하고, 남은 돈으로 채운 정도가 가장 낮은 종목부터 한 단위씩 더 산다.
  - 예수금 목표가 없거나 0%면: 예수금을 남기는 것 자체가 목표에서 벗어나므로, 살 수 있는 단위가 있는 한 계속 산다
    (남는 돈은 가장 작은 매수 단위보다 적다).
  - 예수금 목표가 있으면: 목표와의 차이 합(예수금 포함)이 줄어들 때만 산다. 같으면 단위 때문에 원래 몫보다 반 단위 이상
    덜 산 종목이 목표 대비 예수금보다 더 부족할 때 산다. 남은 돈은 예수금으로.
  예수금 목표가 없으면 남은 돈을 "남는 돈"으로 보여준다
  (현재가를 모르는 1주 단위 종목은 금액만).
  - **현재 예수금도 함께 쓰기** (기본 켬, 기기에 기억): 계산에 쓰는 돈 = 넣을 돈 + 대상 계좌들의 현재 예수금(달러는 오늘 환율로 원화).
    넣을 돈이 0원이어도 예수금으로 계산한다. 예수금을 비중에 넣고 목표가 있으면 계산 후 예수금이 그 목표 근처에 남고,
    목표가 없거나 0%면 예수금까지 최대한 쓴다. 화면에 "사용할 돈: 넣을 돈 + 예수금 = 합계"를 보여준다.
  참고로 "팔기까지 해서 정확히 맞추려면" 종목별 사고팔 금액(목표 × 합계 − 평가금, 매수 단위로 0 쪽 내림)도 보여준다.
  - **해외 양도세 한도 (사고팔기, v2.7)**: 해외 주식 양도소득 기본공제(연 250만원)를 넘지 않도록, 이번 매도까지 합친
    올해 해외 실현손익이 **240만원**(10만원 여유)을 넘지 않게 계산한다.
    - 올해 해외 실현손익(추정): 모든 계좌의 해외(달러) 종목 매도 기록에서 매번 계산한다 (따로 저장하지 않음).
      매도마다 수량 × (매도가 × 매도일 환율 − 원화 평균단가) − 매도 비용 × 환율. 원화 평균단가는 이동평균법(매수일 환율).
      손실은 이익과 상계. 국내 상장 해외 ETF 는 대상이 아니다. 환율이 없는 날은 최신 환율로 추정하고 "추정" 표시.
      실제 신고는 결제일 환율·결제일 귀속이고 매수 수수료도 빼므로 차이가 날 수 있다 (그래서 240만원).
    - 남은 한도 = 240만원 − 올해 실현손익. 해외 매도 중 **손실 매도는 그대로**(한도가 늘어남), **이익 매도는 이익 합계가 남은 한도를
      넘으면 모두 같은 비율로 줄인다**(매수 단위로 내림). 이미 한도를 넘었으면 이익 매도는 하지 않는다. 국내 매도는 상관없다.
    - 덜 판 만큼 매수 금액도 같은 비율로 줄인다 (덜 판 종목은 목표보다 조금 많은 채로 남는다).
    - 계산기 아래에 "해외 양도차익(올해, 추정) · 이번 매도로 생기는 이익 · 합계 / 한도 240만원", 줄였으면 종목별로 줄인 금액.
- 저장: users/{uid}/allocationTargets/{id} = { name, accountIds, targets: { 종목키: % }, excluded: [종목키], names: { 직접 추가한 종목키: 이름 },
  units: { 종목키: 금액 단위(원) }, prices: { 직접 추가한 종목키: 현재가(현지 통화) }, noBuy: [지금 매수 안 함 종목키],
  includeCash, threshold(절대·하단 A), relative(상대·하단 R), upper: { threshold, relative } (상단을 따로 쓸 때만), createdAt }.
  종목코드 없이 직접 추가한 종목의 키는 "manual-kr:…" / "manual-us:…".
  종목·계좌 문서와 분리해 한투 동기화·종목 편집이 덮어쓰지 않는다.

## 2. 목적통장 (목표 탭)

### 2-1. 구조
```
목적통장 (예: IT기기금, 지출)  ← 기대수익률(연 %) 설정
 ├─ 계좌 여러 개 (예: CMA, 채권 계좌) ← 계좌마다 이름·계좌번호·잔액, 잔액은 가끔 직접 입력
 │   → 목적통장 잔액 = 계좌별 잔액 합계
 └─ 목표 여러 개
     ├─ 1회성: 이름, 금액, 날짜          (예: 2028-10-08 노트북 1,000만원)
     └─ 반복:  이름, 금액, 주기(N개월), 다음 날짜 (예: 2년마다 휴대폰 200만원)
 └─ 그룹 여러 개 (함께 살 1회성 목표 묶음, 예: IT 세트 = PC + NAS)
```
- 원화만 사용한다. 잔액은 CMA·채권을 합친 현재 금액을 직접 입력하고, 입력 날짜를 표시한다.

### 2-1-1. 소비 기록 · 구매 완료 (v2.6)
- **반복 목표 [소비 기록]**: 실제로 산 날짜만 고른다 (기본 오늘, 금액은 받지 않음).
  그날부터 주기를 다시 센다 → 다음 지출일 = 소비한 날 + N개월. 지난 소비 날짜는 기록으로 남긴다 (최근 50개).
- 예정일이 지났는데 소비 기록이 없으면 날짜를 **자동으로 넘기지 않고** "예정일 지남 · 소비했으면 기록하세요"로 표시한다.
  (예전 버전에서 만든 반복 목표는 목표를 만든 날 이후의 첫 날짜를 다음 지출일로 본다. 지난 날짜를 넣어 저장하면 주기만큼 더한 날짜로 저장한다.)
- **1회성 목표 [구매 완료]**: "완료한 목표"로 옮기고 잔액 배분·월 납입액 계산에서 뺀다. [되돌리기]로 다시 살린다.
- 소비 기록·구매 완료 뒤에는 "통장 잔액도 고칠까요? [잔액 입력]"을 띄운다 (돈이 나간 것은 잔액을 고쳐야 반영된다).

### 2-1-2. 목표 그룹 (v2.6)
- 목표는 하나씩 만들고, 함께 살 1회성 목표들을 **그룹**으로 묶는다 (예: PC + NAS → "IT 세트"). 반복 목표는 묶지 않는다.
- 그룹: 이름, 구매 날짜(기본: 묶는 목표 중 가장 이른 날짜), 계산 방식 스위치.
  - **하나로 계산 (기본)**: 그룹 날짜 하나, 목표 금액 = 합계, 달성률·월 납입액도 그룹 전체 기준. 그룹 안 목표별 배분은 금액 비율.
  - **개별 계산**: 그룹으로 보여주기만 하고, 각 목표를 원래 날짜로 따로 계산한다.
- 목표는 그룹에 들어가도 원래 날짜를 갖고 있다 (개별 계산·그룹 풀기 때 원래 날짜로 돌아간다).
- 그룹 [구매 완료]는 그룹 안 목표를 한꺼번에 완료한다. 그룹 편집에서 목표를 넣고 빼거나 그룹을 푼다.

### 2-2. 잔액 배분 (가까운 목표부터 채우기)
1. 목표(하나로 계산하는 그룹은 묶음 하나)를 다음 날짜가 가까운 순서로 정렬한다.
2. 통장 잔액을 앞에서부터 각 목표 금액만큼 채운다. 잔액이 다 떨어지면 그 뒤 목표는 0원이다.
   **날짜가 같은 목표끼리는 금액 비율대로 나눈다** (예: 같은 날 200만원·100만원 목표, 잔액 30만원 → 20만원·10만원).
3. **모든 목표를 순서대로 보여준다**: 배분된 금액, 달성률(%), 남은 개월 수, 매달 넣어야 할 금액.
4. 완료한 1회성 목표는 배분하지 않는다.

### 2-3. 매달 넣어야 할 금액 (이자 반영)
- 월 이율 r = (1 + 연 기대수익률)^(1/12) − 1, n = 목표일까지 남은 개월 수, A = 배분된 금액, T = 목표 금액
- 매달 납입액 P = (T − A·(1+r)^n) ÷ (((1+r)^n − 1) ÷ r) (0 이하이면 "달성 예상")
- 통장 단위로 이번 달 총 납입액(목표별 P 합계)을 보여준다.

예시 (IT기기금 통장 잔액 50만원, 연 3.5%, 2026년 10월 기준):

| 목표 | 금액 | 날짜 | 배분 | 달성률 | 월 납입액 |
| --- | --- | --- | --- | --- | --- |
| 휴대폰 (2년마다) | 200만원 | 2027-04 (6개월 후) | 50만원 | 25% | 246,776원 |
| 노트북 (1회) | 1,000만원 | 2028-10 (24개월 후) | 0원 | 0% | 403,075원 |

→ 이번 달 IT기기금 통장 총 납입액: 649,851원

## 3. 앱 업데이트 알림

앱은 GitHub 릴리스(dev-latest)에서 APK 를 받아 설치한다. 새 버전이 나오면 앱이 알려준다.

- 앱을 열 때 GitHub 릴리스(공개 저장소라 인증 불필요)를 확인해, 릴리스의 빌드 번호가 설치된 앱의 빌드 번호(versionCode)보다 크면
  **"새 버전이 있습니다"** 안내와 **설치** 버튼을 보여준다.
- 설치 버튼을 누르면 APK 를 내려받아 설치 화면을 연다. 같은 서명 키라 기존 앱 위에 업데이트되고 데이터·로그인은 유지된다.
- "나중에"를 누르면 그 빌드에 대해서는 다시 묻지 않는다 (다음 빌드가 나오면 다시 안내).
- 설정 화면에 현재 버전(빌드 번호)과 **업데이트 확인** 버튼을 둔다.
- 네트워크 오류 등으로 확인에 실패하면 조용히 넘어간다 (앱 사용을 막지 않음).

## 4. 계정·데이터 삭제
- 설정 화면에 **"내 데이터 전체 삭제 및 탈퇴"**를 둔다.
- 누르면 확인을 두 번 받은 뒤(두 번째는 "삭제" 직접 입력), 이 사용자의 Firestore 데이터(users/{uid} 이하 전부)와
  Firebase 로그인 계정을 삭제하고, 기기에 저장된 API 키·캐시도 지운 뒤 로그인 화면으로 돌아간다.
- 오래전에 로그인했다면 계정 삭제 전에 Google 재로그인을 요구할 수 있다 (Firebase 보안 정책).

## 5. 보안 원칙
- **데이터 분리**: Firestore 보안 규칙으로 로그인한 본인만 자기 데이터(users/{uid} 이하)를 읽고 쓸 수 있다.
- **규칙에서 데이터 형식 검사**: 기능 구현 시 컬렉션별로 허용 필드·타입·값 범위·문자열 길이를 규칙에서 검사해,
  잘못되거나 비정상적으로 큰 데이터 저장을 서버에서 막는다.
- **한국투자증권 API 는 조회 전용**: 시세·잔고·체결 조회 API 만 사용하고, **주문·정정·취소 등 매매 API 는 코드에 넣지 않는다.**
  (공개 저장소라 누구나 코드에서 확인 가능)
- **API 키·계좌 연결 정보는 화면에 다시 전체 표시하지 않는다**: 입력 후에는 앞 몇 자리만 보여주고, 바꿀 때는 새로 입력한다.
- **비밀 정보는 저장소에 두지 않는다**: 서명 키, google-services.json 은 GitHub Secret 에만 둔다.
  사용자 API 키는 기기의 암호화 저장소(Android Keystore)에만 둔다.
- **Firebase API 키 제한**: Google Cloud 콘솔에서 Android 앱(패키지 이름 + 서명 SHA-1)에서만 쓸 수 있게 제한한다.
- **로그에 민감 정보를 남기지 않는다**: 금액, API 키, 토큰을 로그로 출력하지 않는다.
- 기기 백업(allowBackup)은 끈다.

  - 계좌 상세 위 정렬 버튼과 원화/외화 버튼은 한 줄, 환율 설명은 원화 보기일 때만, 티커 색 범례는 ⓘ 를 눌러 본다.
  - 수익률을 계산할 수 없으면(투자금 0) "-" 대신 숨기고, 계좌 상세에 "입금 기록이 없어 수익률을 계산할 수 없어요" 안내.
  - 핵심 숫자 칸은 넘치면 글자를 줄이고, 그래도 넘치면 짧은 금액(예: 329.1만원)으로 보여준다. 위 제목·홈 계좌 이름은 한 줄 말줄임.
  - 목적통장 카드: 금액 아래 "10.10 (토) 기준", 목표 카드는 진행 막대 옆에 %, 금액은 "131.6만 / 600만원". 용어는 "1회성".
  - 입력칸의 원화 금액은 쓰는 동안 쉼표를 붙인다 (1,315,979). 선택된 칩은 진녹색 바탕 + ✓. 삭제 버튼은 빨간 글씨.
  - 저장 버튼이 꺼져 있으면 무엇을 입력해야 하는지 버튼 위에 알려준다.
  - 다크 모드 목표 요약 카드·추가 버튼(FAB)은 진녹색 계열로 통일, 목록 끝에 FAB 높이만큼 여백, 폰은 스크롤하면 FAB 가 작아진다.
  - 폰 자산 추이 그래프 색·범례(선 모양)를 웹과 같게.
  - 티커·계좌 종류 배지는 **고정 폭** (글자 수와 상관없이 같은 크기, 5~6자 코드는 글자를 줄임) → 뒤의 이름 시작 위치가 같다.
    배지가 없는 줄(예수금·미보유 종목)은 같은 폭의 회색 배지("현금", 코드 또는 "티커 없음")로 자리를 맞춘다. 계좌 배지는 짧은 이름(위탁·ISA·연금…).
- 금액 빠른 입력 버튼 (폰·웹): 딱 떨어지는 원화 금액을 적는 곳에만 [+1만] [+5만] [+10만] [+50만] [+100만] [+500만] 을 둔다.
  누를 때마다 더하고, 입력칸의 ✕ 로 비운다. 대상: 계좌 입금·출금·이체 기록의 원화 금액, 목표 금액, 비중 탭 매수 계산기의 넣을 돈.
  (매수·매도 단가, 배당, 예수금, 목적통장 잔액, 외화 금액에는 두지 않는다.)

## 7. PC 웹 (같은 계정으로 PC 브라우저에서 사용)

### 7-1. 방식
- PC 는 **웹사이트**로 쓴다 (설치 없음, 새로고침하면 최신 버전). 크롬 "앱 설치"로 바탕화면 아이콘을 만들 수 있다 (PWA).
- 주소: **GitHub Pages** — `https://ares-wjd.github.io/my-money-tracker/`
- 폰과 **같은 구글 계정**으로 로그인하면 같은 데이터(Firestore users/{uid})를 보고 고친다. 폰·PC 어느 쪽에서 고쳐도 바로 반영된다.
- 데이터 형식·보안 규칙은 폰과 같다 (규칙 변경 없음).

### 7-2. 범위
| 기능 | 웹 | 비고 |
| --- | --- | --- |
| 홈 (평가금·수익률·자산 추이 그래프) | O | 폰과 같은 계산 |
| 계좌 추가·수정·삭제, 종목 추가·수정·삭제 | O | |
| 기록 추가·수정·삭제 (입금·출금·이체·매수·매도·배당) | O | 한투 연결 계좌는 매수·매도 추가 메뉴 숨김 |
| 예수금 입력 | O | 한투 연결 계좌는 숨김 (폰이 불러옴) |
| 종목 현재가 직접 입력, 직접 입력 환율 | O | |
| 목적통장·목표 (추가·수정·삭제, 월 납입액, 소비 기록·구매 완료·그룹) | O | |
| 비중 (비중 설정, 도넛, 매수 계산기) | O | |
| 한투 연결·불러오기, API 키 관리 | X | 폰에서만 (API 키는 폰에만 저장) |
| 현재가·환율 자동 조회 | X | 폰이 Firestore 에 저장한 최신 값을 쓴다. 화면에 "시세 기준 시각" 표시 |
| 앱 업데이트 알림, 탈퇴 | X | 폰에서만 (웹은 로그아웃만) |

- **한투 연결 계좌 구분**: 연결 정보는 폰에만 있으므로, 웹은 한투에서 불러온 기록(externalId 가 "KIS:" 로 시작)이 있는 계좌를 연결 계좌로 본다.
  불러온 기록은 폰과 같이 메모만 고칠 수 있다.
- 시세는 폰 앱이 열려 있을 때 15분마다 저장되므로, 웹의 현재가는 폰에서 마지막으로 저장한 시각 기준이다.

### 7-3. 구현 원칙
- 저장소의 `web/` 폴더. React + TypeScript + Vite, Firebase 웹 SDK (구글 로그인은 팝업 방식).
- 계산 로직(투자금·예수금·평균단가·수익률·그래프·목표 월 납입액)은 core 모듈과 같은 규칙으로 TypeScript 에 옮기고,
  **core 의 단위 테스트 케이스를 그대로 옮겨** 폰과 결과가 같은지 검증한다. 계산 규칙을 바꿀 때는 두 곳을 함께 고친다.
- Firestore 에 쓰는 필드 이름·형식은 폰과 똑같이 맞춘다 (날짜는 "YYYY-MM-DD" 문자열, 금액은 숫자, createdAt 은 밀리초).
- 배포: GitHub Actions 가 빌드·테스트 후 GitHub Pages 로 자동 배포 (새 비밀 값 없음).
  Firebase 웹 설정 값은 저장소에 넣지 않고 GitHub Actions 변수로 넣는다.
- 웹용 Firebase API 키는 GitHub Pages 주소에서만 쓸 수 있게 제한한다.
- 디자인: 폰과 같은 색·글꼴·로고, PC 화면용 배치(왼쪽 메뉴), 화면 모드는 자동/밝게/어둡게 직접 선택 (6. 디자인 참고).
- 자산 추이 그래프: 폰과 같은 보기 단위·계좌 선택·전체 기간, 폰과 같은 저장된 일별 값 (1-5 참고). 과거 종가·환율은 폰 앱이 Firestore 에 받아 둔 것만 쓴다
  (없는 날은 그 전 값). 마우스를 올리거나 화살표 키로 시점을 옮기면 그날 평가금·투자금·수익·누적 배당을 보여주고, 표로도 볼 수 있다.
- 금액 입력칸 아래 미리보기는 원화를 **한글 단위**로 보여준다 (예: 131만 5,979원, 600만원, 1억 5,000만원, 1만원 미만은 5,000원). 폰 앱도 같다.
- 바탕화면 아이콘 설치(PWA): 크롬·엣지의 "앱 설치". 화면은 저장해 두지 않고 항상 최신 버전을 연다.
